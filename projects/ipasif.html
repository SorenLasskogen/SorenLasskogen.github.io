IPASIF

A framework for creating interactive sound installations — wireless, modular, and built so artists can plug in sensors and start playing.

The problem

Interactive sound installations usually need a lot of custom electronics and code, which puts them out of reach for many artists. We started out building a kit for shop-window installations; it grew into a broader framework, focused on wireless communication and modularity, that sound artists can build on.

How we built it

Each sensor sits on its own ESP32. Sender boards stream readings over ESP-NOW to a host board, which forwards them as OSC messages to Pure Data for sound synthesis and TouchDesigner for visuals. Because everything is wireless, an installation can grow in both physical size and number of sensors. We built three use cases to show what the framework can do:

  • Spaceship — a thumbstick and a touch slider fire up an engine, jump to warp speed and coast through space in a synthesised soundscape.
  • Ballin’ — a throwable ball with a BNO055 motion sensor, an ESP32-S2 and a rechargeable battery in a 3D-printed case. Passing it around continuously reshapes the music.
  • What’s in the Box — the motion sensor inside a wooden box, plus two distance sensors that control low- and high-pass filters and the colour of the visuals.

We also explored camera-based input with MediaPipe in TouchDesigner, and refined the framework through three meetings with artists during the semester.

Outcome

44 msAverage latency in stress tests
3Working use cases
2Use cases evaluated with artists

Artists tried two of the use cases and were interviewed afterwards. Key themes were playful, creative exploration; some confusion about exactly what the framework can do and a wish for more control; potential for social interaction; flexibility beyond sound installations; and creative inspiration. Stress tests also showed satisfactory wireless range.

In its current form the framework suits technically confident artists, or artists working with a technical collaborator. More sensor types, lower latency, a GUI and better documentation are the next steps.
